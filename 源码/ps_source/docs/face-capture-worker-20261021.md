## 实现与边界

- `ps_app/src/wcis_camera_owner.cpp` 保留一个iCraft Device和一个分配器，SDK命令仍只在主线程执行。参考厂商 `ps_app/vendor/include/pipeline/actor/sdicamera_input_actor.hpp` 的独立输入线程与缓冲区归还模式，将采集、格式转换、VPU编码和最新帧发布交给固定线程。
- 主线程预分配两块UDMA缓冲，核对原有地址窗口、对齐及互不重叠；启动时分别将两块CPU映射的原始帧与SDK读回逐字节对比。运行中的采集线程直接复制既有映射，不调用iCraft SDK、分配器、NPU复位或FAC1接口。
- 新增 `ps_app/src/wcis_camera_mmio.hpp`，仅映射已核对设计的摄像头页 `0x40080000`。先比较SDK与直接映射的固件、配置和SDI2寄存器，线程写入只允许请求及写地址两项；保留锁定状态、错误位、请求清除旧DONE、完成超时和当前启动故障检查。
- 交替DMA缓冲读完才允许再次使用；发布后的原始帧/JPEG组成不可变对象，识别快照持有该对象，视频继续更新也不会修改识别源帧。保留最新帧，不积压推理任务或历史视频队列。
- 停止时先停止并等待采集线程退出，再排空末次相机DMA和VPU，最后释放内存及关闭SDK。

这仍使用现有PL单帧采集分支，由PS线程持续提交请求；本轮没有实现PL自主环形DMA，没有打开原例程写地址相同的continuous模式，也没有改RTL、引脚或时钟。

## 发现并修正的完成边界

第一版在纯采集15fps测试后，模型负载下异常退出；一次复测通过24次摄像头请求，但随后压力测试再次退出。保留的原生日志确认退出码3，原因是 `Retained frame output canary remains`，不是板机失去SSH。失败时停止继续使用候选；人工核对相机请求已结束、FAC1完成且无错误位、正式应用及启动配置未改后，归档故障标记并恢复原服务，双人照片回归通过。未自动忽略故障或重启SDK反复尝试。

`ps_app/src/wcis_owner_kernels.hpp` 的PL完成条件补充为：

1. START前完整读回并确认本次输出区都是初始化标记A5，建立本次写入的新边界。
2. 等待原有FAC1完成标志，并检查错误、帧ID和像素数。
3. 完成后读回输出，直到每个像素的alpha字节均被PL写为零，才交给后续模型。只继续读取同一次操作的结果，不重新提交PL任务；初始化及完成读回各有2秒上限，失败仍隔离设备。
4. 保留源帧守卫、分配重叠检查及输出格式校验；异常信息额外保存到原生程序目录，避免临时工作区清理后丢失最初原因。

修正后的109次PL变换中，实测一次完成后的首次读取仍有784个像素未写完，第二次读取完整。该证据确认“完成标志已返回”与“CPU读取到完整输出”存在窗口。RTL `rtl/wcis_face_customop.v` 说明原生写端没有DDR写响应；本轮增加软件可见性验收，没有宣称已通过ILA定位DDR内部的具体排序时序。初始化标记和完整输出检查均保留，未通过取消检查、放宽识别阈值或接受部分数据提帧。
