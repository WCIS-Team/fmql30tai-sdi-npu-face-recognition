# 500 MHz 候选上板对照（2026-10-23）

## 结论与当前状态

500 MHz 分频候选通过本轮有界上板功能和负载测试；当前已按约定恢复测试前原镜像，摄像头/识别服务 ready。它可以作为后续验收候选，不能据此宣称厂商硅片签核完成或实际 NPU 内核频率已测得。

离线修改及完整时序证据见 [2026-10-22 离线记录](D:/renlianshibie/fpga_project/docs/npu-clock-500mhz-experiment-20261022.md)。本轮直接复用冻结位流，没有重新综合、布局布线、编译模型或交叉编译程序。

## 对照方法与结果

1 GHz 对照和 500 MHz 候选使用同一份优化后的 RTL/实现基线，唯一预期配置差异为真实 PLL 的 CLKOUT0_DIVIDE 1→2；原已验收镜像只作最终回退目标，不作为相同 RTL 的性能对照。三份 BOOT 和全部启动支持文件经 SHA256 核对，FSBL/BL31/U-Boot 不变。先确认新 boot ID、SD 上目标镜像和独占硬件所有权，再做回归；基本检查通过后才临时接入原服务。每次实验启动带 600 秒回退定时器。

- 1 GHz boot ID：`a2b7f273-9bba-4a05-8877-7ba2ca6b8464`。
- 500 MHz boot ID：`d865a3ea-860f-47dc-80a6-15d4a8f5e39b`。
- 两版均通过 4 个 SDK 分配缓冲区的写入/双次读回，零不匹配；这不代表完整 2 GB DDR 容量验证。
- 两版均通过 8 个像素用例，共 88 次回归，含全源图读回核对。
- 两版均通过 11 张公开图片、7 个留出识别检查和无人脸/多人脸边界检查；24 组 YuNet/MobileFaceNet 原始输出逐文件哈希完全一致。
- 两版各进行至少 60 秒 HTTP 识别与 SDI/VPU 采集并行负载；分别完成 87 / 87 次图片识别、各 3 次摄像头识别和各 3 张预览 JPEG 解码（960×540×3）。固定图片输出及身份结果全程一致。

## 中断、失败及修正

10 月 22 日的首次 1 GHz 试跑在结果汇总前中断，回退定时器已恢复原镜像；该轮不计作完整 A/B 验收。10 月 23 日首轮的模型测试通过，但人员库保护检查拦下实验，随后原镜像和服务恢复。恢复后全部人员库哈希与测试前相同，未发现人员资料修改。脚本停用识别服务后，没有主动带起其依赖的静态存储挂载服务，可能把未挂载目录当空人员库；失败当刻没有保存挂载快照，此根因属于依据服务依赖和复测结果作出的判断。修正为显式启动原存储服务，并核对实际挂载源为 /dev/mmcblk1p1，再做原有完整性检查。独立 r2 目录重新测试两版并通过，未删除或放宽人员库检查。

## 验证边界

500 MHz 是已写入候选位流的 PLL 输出配置及工具自动推导值。没有用仪器或硬件计数器测实际 NPU 内核频率；SDK 时间包含主机、会话、读写等开销，性能数据不能反推硬核频率。当前证据未给出该 PLL 与 NPU 硬核频率的完整对应关系。

本轮只验收 YuNet/MobileFaceNet，不覆盖 ASR/LLM 或多模型共存。未测试断电冷启动循环、长时间/温压边界稳定性、PL JPEG 编码器、防照片/视频攻击和门锁授权安全。本轮预览使用当前 VPU JPEG 路径。离线 setup/hold 最小余量仍为 0.005/0.004 ns，代理器件模型适用性和厂商正式保证仍需单独核实。
