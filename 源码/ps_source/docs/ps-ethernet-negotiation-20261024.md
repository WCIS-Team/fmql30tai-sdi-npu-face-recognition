板端 `ethtool eth0` 明确报告链路伙伴只广播 10/100，未广播 1000。当前板端并未被软件强制限制为 100 Mbps；活动设备树未发现 `max-speed=100`，两个以太网节点的 `phy-mode` 都是 rgmii。板端 EEE 关闭。

102 上没有安装 ethtool。用 Python ctypes 通过只读 `SIOCETHTOOL / ETHTOOL_GSET` 查询实际驱动能力，没有安装软件或调用设置接口：supported 与 advertising 均为 0x62cf，没有 1000baseT 位；PCI sysfs 实读 10ec:8136。Linux v6.12 与当前 102 的 6.12 系列相符，源码将该 PCI ID 标记为 `RTL_CFG_NO_GBIT`；这是网卡能力限制，不能靠 `ethtool -s` 增加千兆支持。不能由 r8169 驱动名推断网卡一定是千兆。

## 排除范围与未确定项

单次计数快照中，两端 RX 错误、CRC 错误、丢包均为 0；网关 TX 错误 0。板端 TX 错误 1，与驱动累计 underflow 1 对应，不能把这个历史累计值说成持续发送错误，也没有依据将其当作协商百兆的原因。carrier_changes 均为 2；没有做长时稳定性结论。板端本次启动日志明确从启动起就协商为 100Mbps/Full。

102 网卡只支持百兆，是当前经过 102 的传输路线中已经确认的硬限制。板端直接相连的伙伴也只广播百兆，但软件无法仅由同网段路由/邻居项证明两根线之间是否有交换机。

- 若板端 PS 网口直接连 102 的 enp2s0，根因即为 102 的百兆网卡，当前协商符合双方能力。
- 若经路由器/交换机，板端那一跳还要核对交换机端口是否只有百兆或被配置为百兆；102 的百兆网卡仍会限制经过它的后续传输。
- 线缆完整四对是否满足千兆、真正千兆对端下能否协商/稳定运行，当前尚未验证，不能声称所有硬件问题均已排除。
