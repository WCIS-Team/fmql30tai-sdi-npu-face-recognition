## 连接目标

```text
本机
  → 跳板机：user@192.168.1.102，SSH 默认端口 22
  → 学校服务器：YiZhidi@127.0.0.1:13401
```

这里的 `127.0.0.1:13401` 是从跳板机访问的地址，不是本机的回环地址。跳板机使用密码认证，学校服务器使用本机的 Ed25519 私钥认证。辅助脚本中用户名写作 `yizhidi`，已成功登录同一 Windows 账户。

学校服务器为 Windows；用户提供的限制是没有管理员权限、WSL 或 GPU。可使用已有 MSYS2 和 Windows 交叉编译工具，不能据此假定有 Vivado、Procise 或 NPU 模型转换工具。

## 手动连接

不依赖 SSH 别名，在本机 PowerShell 执行：

```powershell
ssh -J user@192.168.1.102 -p 13401 -i "C:/Users/anxianji/.codex/credentials/school-ed25519" YiZhidi@127.0.0.1 "D:/yzd/MSYS2/usr/bin/bash.exe --login -i"
```

按提示输入跳板密码。这个手动命令根据已验证的连接参数整理，本次没有执行；实际成功记录来自项目辅助脚本。OpenSSH 使用自己的主机密钥记录，不能默认它已经信任辅助脚本固定的主机密钥。

若要使用原来的 `school-guest` 命令，可在本机 `C:/Users/anxianji/.ssh/config` 配置以下条目。同名条目已存在时应核对并更新原条目，不要重复追加。本次没有修改 SSH 配置。

```sshconfig
Host school-guest
    HostName 127.0.0.1
    Port 13401
    User YiZhidi
    IdentityFile C:/Users/anxianji/.codex/credentials/school-ed25519
    IdentitiesOnly yes
    ProxyJump user@192.168.1.102
```

配置后执行：

```powershell
ssh school-guest "D:/yzd/MSYS2/usr/bin/bash.exe --login -i"
```

## 服务器实际使用的公钥路径

学校 SSH 服务是账户自己启动的 OpenSSH 服务，用户提供的启动参数为：

```text
C:/Users/YiZhidi/sshserver/OpenSSH-Win64/sshd.exe
  -f C:/Users/YiZhidi/sshserver/sshd_config
  -E C:/Users/YiZhidi/sshserver/sshd.log
```

实际配置明确指定：

```text
AuthorizedKeysFile C:/Users/YiZhidi/sshserver/authorized_keys
```

此前将公钥加入账户 `.ssh/authorized_keys` 后仍无法认证；追加到上述实际读取的文件后，登录成功。因此遇到公钥拒绝时，先核对服务进程所用配置和 `AuthorizedKeysFile`，不能默认使用 Windows 系统 SSH 配置或账户默认目录。

## 常见问题与证据边界

| 表现 | 优先核对 |
|---|---|
| `Could not resolve hostname school-guest` | 本机是否配置了别名；也可使用不依赖别名的完整命令 |
| 公钥被拒绝 | 目标账户、端口、所用私钥及服务实际读取的 authorized_keys；不要换成隧道私钥 |
| 找不到 CMake / Ninja | 工具文件是否存在，以及当前进程 PATH；不等于服务器没安装 |
| 主机密钥不匹配 | 核实是否换了主机或重装服务；不要直接删除已有信任记录 |
| Windows 编译成功，板端提示 GLIBC 版本缺失 | 核对工具链 sysroot 和板端 ABI；生成 AArch64 ELF 不代表运行兼容 |
