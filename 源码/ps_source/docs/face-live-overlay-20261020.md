## 信息来源与实现

读取项目AGENTS、`D:/xiangmuwendang/WCIS-FPAI/wiki/PL/plvid.md`、原摄像头互斥接入记录及实际源码。该背景材料中的SFace说明与当前实际YuNet + MobileFaceNet部署不同，以当前配置和实测为准。此次按用户明确提出的画面及检测信息需求补充界面。

- `npu_photo/camera_panel.html`、`camera_panel.js`：画面与结果在同一面板，按各脸的`face_index`关联身份。在对应原始图像坐标绘制框与关键点；模式切换后忽略旧请求的晚到响应，登记/上传前等待本页在途检测完成。检测异常暂停自动检测，不自动重试SDK。
- `npu_photo/serve_photos.py`：新增只读 `GET /api/camera/preview.jpg`，返回JPEG及会话、帧号；摄像头识别响应直接内嵌模型输入的原JPEG，避免另行压缩或抓取下一帧引入框错位。摄像头请求使用`/dev/shm`临时目录并在结束后删除，保留原照片上传逻辑。
- `npu_photo/recognize_photo.py`：增加默认开启的`save_aligned`参数；摄像头关闭对齐小图落盘，原照片行为保持默认。
- `npu_photo/camera_interlock.py`：修复连续请求时首帧尚未发布的竞争条件。服务启动返回后，最多4秒只读等待当前会话与新鲜帧；每轮核验启动证明、隔离标记和服务状态，不重试SDK。先前直接读取旧会话目录会发生文件不存在。
- 预览在推理或采集刚恢复时返回503是暂态；页面等待下一次只读预览，不把旧框套到新画面上。修正前验收脚本对一次即时预览503判失败，现改为有界等候新帧，保留边界。

页面集成源、部署脚本、原页面与备份清单在 `D:/yzd/tmp/face-live-overlay-20261020`。板上应用仍为 `/root/wcis-face/apps/camera-ready-20261020`；独立任务备份在 `/root/wcis-face/candidates/face-live-overlay-20261020`。部署只停止并启动照片服务，摄像头服务由原互斥机制控制。
