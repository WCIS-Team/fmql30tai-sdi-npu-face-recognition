# 接口与兼容边界

## 已接入的整帧选择

`wcis_frame_rate_gate` 输入为案例内部 RGB888 DVP：`s_vsync` 上升沿表示帧边界，`s_href` 表示有效像素，`s_data[23:0]` 透传色序。输出三者一起延迟一个 camera 时钟。没有 source ready；被丢弃的帧仍被 SDI 接收器完整接收，只是不交给后级。

选帧算法以实际到达的帧为单位。工作状态（30→20）依次丢／留／留；待机（30→1）每第 30 帧保留。每次提交重新从零累计，因此进入待机后首帧可能要等待约 1 秒。不承诺 NPU 完成 20 次/秒，也没有多模型调度器。

源帧率参数在 `case/rtl/display/frame_trans.sv` 的 `rate_gate` 实例中设为 30，工作 20、待机 1。真实输入的稳定到达率需上板重新核对；不把历史的 30.06 次交付/秒当作摄像头物理 SDI 制式或线速率的证明。

### 寄存器

相对原 camera 控制寄存器基址的偏移（源码中基址为 `0x40080000`，部署前对照现役地址）：

| 偏移 | 读写 | 内容 |
|---|---|---|
| `0xB8` | 写 | 低字节 strobe 有效时，bit1＝选帧 enable，bit0＝active。写 `1` 旁路、`2` 待机、`3` 工作 |
| `0xB8` | 读 | bit1:0 为最近接受的配置，bit2 为忙时写入被拒绝标记；下一次成功接受清除 bit2 |
| `0xBC` | 读 | bit1:0 为 camera 帧边界已应用并回 ACK 的配置；bit3 为 pending/busy |
| `0xC0` | 只读 | `0x57434953`（WCIS），识别这份寄存器扩展，防止把模式控制写给旧位流 |

旧 `0x00..0xB4` 偏移保留。忙时新写入不覆盖正在传递的数据，AXI 总线事务仍结束，应用须读回判定；不能把写寄存器成功当作已生效。无输入帧时 pending 保持是预期行为，不能无限等待。

mailbox 流程：配置时钟域持有 2 位配置 → 请求 toggle 经两级同步 → camera 域在帧边界使用保持的数据 → ACK toggle 回传 → PS 可以发下一次配置。reset 默认旁路，两域 reset 由同一个组合输入触发，各域同步释放。camera reset 后应重新读取 applied 状态并重发需要的模式；B8 的历史请求值不等于当前 applied。

`seen_frames`、`selected_frames`、`dropped_frames` 为 camera 时钟域计数器，已留 ILA `mark_debug`。没有把 32 位计数总线直接跨到 AXI-Lite；当前不提供 PS 实时读取这些计数的寄存器。它们表示进入前端的帧数，不表示 NPU 完成次数。

### PS 超时必须配套

原 SDK `SDICamera::wait(int wait_time_ms = 100)` 默认只有 100 ms，待机模式最长约 1 秒才开始下一次取帧。启用 1 fps 前，应用调用 `wait(1500)` 等足够的超时，并把输入故障超时与正常待机等待分开。这里不修改 Downloads 的 PS SDK，也不宣称旧二进制在待机模式下无需变化。

`include/wcis_rate_gate.hpp` 提供可接到现有 iCraft Device 的 C++17 控制辅助函数，检查扩展 ID、忙、拒绝写入和帧边界 ACK，使用单调时钟限时等待。它没有创建新的映射或 NPU 会话，也没有在板上编译／部署。

```cpp
// 在现有程序中使用同一个 device；相机超时也要同步修改。
auto result = wcis::set_vision_mode(device, wcis::VisionMode::Standby);
// result == Applied 才代表 camera 域已应用，超时可能是没有输入帧。
// SDK 对应的取帧处改为 camera.wait(1500)，而不继续使用 wait() 默认值。
```

原案例 FIFO 深度只吸收短时积压，不能吸收 NPU 长期慢于摄像头的速率差。选帧减轻压力，但没有修复下游任意长停顿造成的溢出。收到相应 FIFO error 时应丢弃该次结果并走原恢复通路；恢复效果需板端验证。

## 原裁切／抽样的已验证尺寸

`cmos_resize_24bit.v` 保留原采样规则，仅为改善配置到数据寄存器的路径去掉输出 payload 的 clock-enable。数据只在 `resize_href=1` 时有意义；逐个有效像素的比对已通过。它选择已有像素，没有四邻点插值。

| 输出 w×h | 源帧 | 保留范围（闭区间） | 步长 | 仿真实际采样原像素坐标 |
|---|---|---|---|---|
| 640×352 | 1920×1080 | x=0..1919，y=12..1067 | 3,3 | x=2+3i，y=14+3j |
| 960×512 | 1920×1080 | x=0..1919，y=28..1051 | 2,2 | x=1+2i，y=29+2j |

960×512 这条是中心裁切 1920×1024 再抽样，属于原案例的整数抽样路线。它与 YOLOv8 PSIN 的全图等比缩放＋右下补边不是同一种前处理，不能直接共用精度结果或框坐标还原规则。

## 独立补边模块

本轮 VTC 重写与登记照片/实时人脸的共同处理要求见
[rtl-rewrite-20261013.md](rtl-rewrite-20261013.md)。VTC 的 VS/HS/DE/RGB
统一经过两级寄存器，RGB 仅在 DE=1 时有效；停流配置后至少保持 4 个
camera 时钟才选择 VTC。它仍不提供旧多位时序配置的原子 CDC。

`wcis_stream_letterbox` 输入已经缩放好的 RGB888 像素流，采用 `valid/ready`。输出 `m_sof/m_eol/m_eof` 跟随有效像素，反压时与数据一起保持。参数包括内容尺寸、画布尺寸、左／上 padding 和填充值，默认 640×360 → 640×640，右／下补边，填 114。

这只是补边，**没有 resize、颜色交换、归一化、五点对齐**。它支持 1×1 和无 padding，尺寸静态配置。上游每帧必须准确送 `CONTENT_W×CONTENT_H` 个像素并在 stalled 时保持数据；复位会取消当前帧，上游也要从下一完整帧重新开始。

没有把它直接接到旧 ImageMake：旧 `img_start` 是与 FIFO 数据分离的跨时钟脉冲，而这里的 SOF 是像素握手标志；两者不能直接接同一根线。补边的额外像素／间隙还会改变 FIFO 积压与 ImageMake 帧长，必须连同模型图、buffer 大小和框回映射一起集成。

## 当前模型状态

| 路线 | 本版状态 |
|---|---|
| 原 YOLOv5 PLIN 案例 | 保留硬件通路及寄存器；本次没有跑板端程序 |
| YOLOv8n 960×512 | 原抽样路线能产生该尺寸，但尚未验证等价前处理和对应 PLIN 模型图 |
| YuNet 640×640 | DDR 仿射缩放/黑色补边经官方 CustomOp 接入整板，文件输入PL+NPU板端联合检查通过；旧实时 PLIN 链路与模型图尚未接入，非整数尺寸存在定点误差 |
| MobileFaceNet 112×112 | PS 五点矩阵→PL 原帧采样已上板，11张照片与CPU参考特征余弦0.9971～0.9998；不是摄像头或身份识别准确率验收，也不能用整帧缩小替代对齐 |
