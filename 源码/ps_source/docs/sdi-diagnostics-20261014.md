## 新接口的数据流

`rx_sdi` 恢复时钟、传输锁定与格式、真实 RGB 的 VS/DE
→ `ps_ai_peripheral` → `frame_trans/sdi_monitor`
→ 在 AXI 时钟域提交完整快照 → `frame_ctrl` 的只读寄存器。

监测点在 VTC 源选择和选帧之前，硬件测试图不会增加真实输入计数。
保留 AI_Mate 及现有 PS→PL 控制桥；没有修改引脚、GT 时钟拓扑、采集控制或旧寄存器。
`0xB8/0xBC/0xC0` 仍属于 WCIS 选帧扩展，不能当作 SDI 状态。

## SDI2 v1 寄存器

相对于已核实的 camera 寄存器基址（现有接口为 `0x40080000`）。
**现装厂商位流不含此接口，禁止把下表当成当前板端实测。**

| 偏移 | 内容 |
|---|---|
| 0x100 | 身份 `0x53444932`，ASCII SDI2 |
| 0x104 | 协议版本 1 |
| 0x108 | bit0 已收到快照，bit1 新鲜，bit2 请求未应答，bit3 参考时钟 MMCM locked，bit4 外部 GT 复位输入已释放 |
| 0x10C | 快照序号，提交完整快照时递增 |
| 0x110 | 提交时的 CFG 周期计数（32位回绕） |
| 0x114 | 距上次提交的 CFG 周期数，饱和到 UINT32_MAX |
| 0x118 | bit0 传输锁定，bit2:1 SDI模式，bit6:3 family，bit10:7 rate，bit11 scan |
| 0x11C | RX 时钟域运行周期累计数（32位回绕） |
| 0x120 | 锁定期间真实 VS 上升沿累计数 |
| 0x124 | 锁定期间真实 DE 上升沿累计数 |
| 0x128 | 锁定期间真实 DE 有效周期累计数 |
| 0x12C | 最近完整 VS 间隔测得的 active 高度[31:16]、最大行宽[15:0] |
| 0x130 | CFG 配置频率，当前参考源为 50,000,000 Hz |

CFG 频率来自 `demo_clkrst_wrapper.v` 中 gp_clk=ps_clk_out 与当前参考设计
50MHz 时钟约束，不是对晶振的独立测量。默认 10ms 请求快照，100ms 无提交即失效。
RX 不运行时 CFG 仍能响应读取，旧锁定位不可被软件当成当前锁定。
外部复位输入已释放、MMCM locked、传输锁定是不同状态；不能把任一位等同于
GT CDR/PLL 全部已锁定。RX 自由运行频率也不能无条件解释成有效像素频率。

几何统计饱和到 65535，只用于当前小于4096维度的诊断；隔行输入得到的可能是
场/传输区间，不自动做场合并。格式编码描述传输，不保证等同于实际画面格式。
解码依据 AMD/Xilinx PG071 表3-1、3-2及 RX 端口说明：
https://docs.amd.com/api/khub/documents/7~l39XeHWsuzRs6bB2eCHg/content
与本地 v3.0 IP 的 rx_t_scan 定义一致（0隔行、1逐行）。

## 一致性与跨时钟规则

- 共同复位异步断言，各域两级同步释放；源时钟停止时仍能清零请求/应答。
- CFG 发请求 toggle，RX 将状态和计数锁存在 payload_hold 后应答。
- 应答两级同步到 CFG，在后续时钟边沿整体提交 snapshot。
- 未应答的请求永远不撤销/复用，恢复时钟后的迟到应答仍对应同一请求。
- 软件先检查 SDI2 身份/版本，序号前后相等才接受快照；最多重读3次。
  读取 helper 仅实现一致性，不授权访问未知位流；必须先验证实际控制桥和固件。
- 单 bit 只切到第一级同步器；payload 到 snapshot 有20ns max-delay与bus-skew约束。
  这些完整整板布线的约束还需要复验。

## 尚不能部署的原因与下一步

补充核实：已直接阅读/渲染原版《悟净开发板硬件使用手册V1.0_集创赛》
第16、27、37、40页。第16页的 SDI 晶振标称148.5MHz，与时钟 IP 配置及1:1
比例相符；此前156.25MHz注释不再单独作为错误证据。J27 1-2短接选 SDI
板载时钟、2-3短接选 SMA 外部时钟，实际位置仍未确认。第6页整板照片没有标注
J27，不能据原理图猜实物位置。手册第37页把数据选择写为J12，第40页却写J26，
编号存在冲突，应按实际 GTX_LANE_SEL 丝印核对，不直接指导移动。
只读 Linux 时钟清单可读取，但没有 I2C adapter、没有 Linux 管理的 SDI/Si570
时钟项，因此这份清单不能测得板上 GT 参考时钟，也不能从软件直接改变 J27。
该时钟清单检查不打开SDK；后续单次SDK检查见本页开头。没有再次触发采集。

1. 参考时钟注释与 IP 参数不一致：`rx_sdi.v` 标注输入156.25MHz；
   `mgtclk_clk_wiz.v` 的 CLKIN1_PERIOD=6.734ns（148.5MHz），
   CLKFBOUT_MULT_F=6.750、DIVCLK_DIVIDE=1、CLKOUT0_DIVIDE_F=6.750，实质1:1。
   因此该 IP 并没有实现156.25→148.5转换。**注释可能旧、实际输入可能不同、
   厂商2025位流可能有另一套实现**，不能据此认定当前实机时钟错误。
2. 本地 XDC 的 R6/R5 注释为Lite、U6/U5为Full；这只是源码标注。
   仓库历史还记录相同厂商配置曾出画面，并曾纠正过盲目改引脚。
   不能仅按板型名称选引脚；当前部署位流引脚映射尚未读回，不修改引脚。
3. 旧完整工程仍有 WPWS -0.409ns；默认 DRC 的 REQP-52/56 指向
   GTGREFCLK（通用时钟驱动 GT）的兼容性，而不是 SHD30 帧率白名单。
   FMQL 厂商实现与 Xilinx 代理模型的差异必须按厂商证据核实，不能直接忽略。
4. 新 SDI2 尚无完整整板综合/布局布线、BOOT打包与兼容性验收。

先核对这份工程的实际参考时钟/GT通路与厂商配置，再完成新接口整板构建。
达到可部署条件后才能生成独立候选 BOOT、保留恢复文件并做受控替换；
不能再次删除 AI_Mate 来换取一个容易构建的诊断位流。
当前只读软件不会读取新的状态寄存器，不消费原取帧失败标记。
