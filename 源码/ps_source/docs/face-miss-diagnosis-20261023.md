## 用固定输入定位

从此前 500 MHz 真人采样响应提取 18 张实际被选中推理的 JPEG，逐一核对 SHA256 与 result.photo_sha256 一致，保留帧号；未拿异步预览帧替代推理帧。CPU 使用校验过的原始 YuNet ONNX，SHA256 为 8f2383e4dd3cfbb4553ea8718107fc0423210dc964f9f4280604804ed2552fa4。

从实际部署的 run_photos.py 读取 prepare/decode，并与本地版本做 AST 比较，两个函数一致。CPU 参考沿用 640×640 等比缩放、右/下补零、BGR 输入、0.6 检测阈值和 0.3 NMS；原始 ONNX 已带 sigmoid，部署的 FP16 NPU 模型则使用配置中的 host_sigmoid。两条路径激活契约分别遵守，没有重复施加 sigmoid。

18 张保存帧的 CPU 检出数与此前现场结果 **18/18 一致**，同样只检出其中 3 张；其余 15 张的 CPU 最高候选分数为 0.084～0.459，低于 0.6。单脸、双脸、无脸三张公开控制图的 CPU 结果分别为 1、2、0，均符合预期。它支持原始模型在这批输入上也会漏检，未发现仅限 PL/NPU 路径的计数差异；JPEG 与原 RGB565 不完全相同，不能把计数一致当作所有输入的逐像素或原始张量等价证明。

## 用户调整后实拍

用户按提示调整摄像头角度、正面姿态和照明后确认可以采样。本轮只调用原服务的识别接口，没有重启。第一次请求返回 HTTP 409 服务忙；随后诊断脚本只对 409 做短暂退避，不强占 SDK、不处理硬件错误重试。成功采样中记录 17 次忙响应和 11 次成功识别，实际采样窗口 6.36 秒。

11 次成功请求全部一张脸，检测分数 0.934～0.943，全部 unknown。有脸请求板内 HTTP 耗时中位数 475.7 ms、最大 488.7 ms；这是有其他请求竞争时的端到端耗时，不是纯 NPU 时间或最大吞吐。

提取这 11 次的精确所选 JPEG，再由学校服务器 CPU 原始模型复算，同样 11/11 检出一张脸，最高分约 0.934～0.940。该组与旧组拍摄条件不同，不能把 3/18 与 11/11 当作严格单变量统计；但它给出了不改模型/阈值即可改善当前连续检出的直接证据。
