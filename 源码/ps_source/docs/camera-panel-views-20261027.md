# 自适应检测间隔、帧率、主视图切换与防伪叠字（2026-10-27）

## 需求与实现

用户在检测小窗提速后要求：无人脸降低检测频率，有人脸保留 50 毫秒间隔；显示帧率；点击检测图放大并缩小预览，点击预览反向切换。工作中又要求把防伪结果明确显示出来。

- `npu_photo/camera_panel.js` 按最近成功结果的 `face_count` 选择下一轮等待：零张脸为 1000 毫秒，大于零为 50 毫秒。均从本次请求和对应图片加载完成后起算，不是 1 Hz/20 Hz 的完成率保证。初次打开立即检测；单页单请求、手动复用、暂停、隐藏页面和 409/429 的指数退避保持。
- `npu_photo/camera_panel.html` 将预览、检测图和信息栏分为稳定的网格区域，用布局类交换大小。保留同一视频元素和地址、同一检测画布，切换不请求推理、不重连预览。鼠标、Enter 与空格均可操作；没有检测图时不放大空白画布。窄屏样式保留主次两图，信息栏放在下方。
- 新增“预览源帧率”和“检测更新率”。前者根据服务端已发布帧数的增量估计，不冒称浏览器解码/显示帧率；后者按不同检测帧实际显示的时间间隔统计最近最多 8 个样本，不用源帧号跳跃推算处理帧数。暂停、页面隐藏、采集会话变化会相应标记或重置；已有统计且超过三秒无更新时显示 0.0 fps。
- 防伪汇总移到侧栏顶部的独立状态卡，每张脸的框旁增加防伪文字。多人按 `face_index` 绑定，不按返回数组顺序误配。显示模型判断为真人、疑似攻击、不确定、未评估/超限、失败、失效/过期等状态，身份匹配不代替防伪结论。
- 画布叠字沿用同帧/会话/boot/原帧散列及证据时效检查。每 250 毫秒检查时效，仅当标签状态改变时，从保存的对应 JPEG 重画标签；不额外推理，不把已经画入画布的旧真人标签永久保留。显式暂停及源失效也替换旧标签。

没有更换模型、阈值、位流、硬件所有者或录像设置；未修改后端推理算法和安全校准状态。

## 验证
