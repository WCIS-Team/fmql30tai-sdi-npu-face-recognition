# PL 原始画面直送 VPU：验证结论与共存阻塞（2026-10-29）

**结论：1080p UYVY 原始画面直送 VPU 已在隔离条件下验证通过，但 VPU 与 NPU 共存未通过，因此未部署；正式系统保持优化后的 960×540 PS/VPU JPEG。本轮没有修改 RTL、位流、BOOT、引脚或模型。本文是这条线的收口记录，供后续文档引用。**

> **后续（2026-10-30）**：正式系统已切换为 540p H.264（`camera-h264-20261030-r1`）；本文“正式系统保持 960×540 PS/VPU JPEG”仅指 10-29 当时。完整 1080p 直送与 NPU 共存仍未通过，见 [H.264 标准实现](h264-ffmpeg-20261030.md)。

## 可直接引用的事实

1. **格式直送已通过**：PL 输出 1920×1080 UYVY，PS 不做颜色转换，直接作为 VPU 输入。真实 SDI + 独立采集线程 → VPU H.264，900 帧 / 29.947 秒（约 30 fps），900 帧全部解码，进程约 0.249 核。固定内存输入 240 帧 / 8 秒同样通过。
2. **JPEG 路径也通过过纯内存验证**：同一 UYVY 输入、质量 80，302 帧全部解码为 1920×1080；重复输入同一帧时输出 SHA256 唯一。
3. **没有做零拷贝**：采集后仍有整帧 memcpy（1080p 约 2.43 ms/帧）；厂商 VPU 封装只使用 `V4L2_MEMORY_MMAP`，没有 DMABUF/USERPTR 路径。不能表述为“数据不经过 CPU”。
4. **共存未通过**：VPU 编码与 NPU 模型活动同时存在时出现编码停帧；日志停在 VPU 输入 `VIDIOC_DQBUF`，并出现 MVX watchdog。把 VPU 分到独立进程、固定内存输入、SDK owner 禁用摄像头仍复现；540p H.264 对照同样在模型负载下停帧。当前 540p JPEG + NPU 的正式组合正常。
5. **分时方案能跑但慢**：暂停采集、排空后编码，识别请求期间约 4.17 fps，空闲约 30 fps；不作为直播交付。
6. **正式系统未切换**：仍为 `camera-psopt-20261029` + `recording-psopt-20261029`，540p JPEG；两进程空闲合计 0.6380→0.3896 核，发布速率 29.75→29.77 fps。

## 证据与边界

| 用例 | 结果 | 边界 |
|---|---|---|
| 固定内存 UYVY→VPU H.264 | 240 帧 / 8.00 s，1920×1080 Main、无 B 帧，全帧解码、MP4 封装通过 | 无真实采集、无 NPU；样本复杂度有限 |
| 真实 SDI 1080p、独立采集线程→VPU H.264 | 900 帧 / 29.947 s，900 帧全部解码，约 0.249 核 | 约 30 秒原型；未接网页、录像或 NPU |
| 每轮采集→排空→编码→排空（JPEG） | 602 帧 / 60.49 s，其中 600 帧来自新采集，全部解码 | 约 9.92 fps；不是正式部署或长稳 |
| VPU 与 NPU 分进程、固定内存 | NPU 完成 12 次单脸重放；VPU 约第 84 次提交阻塞，MVX watchdog | 跨进程未解决共存 |
| 540p RGB565→CPU NV12→H.264 对照 | 空闲约 26.01 fps、0.316 核 | 模型负载下也停帧，不能只归因 1080p |

上述窗口都没有覆盖：明亮真人场景、与身份/PAD 并发的长期运行、网页播放、MP4 正式录像、断电恢复。`900 帧 / 30 fps` 是 30 秒独立窗口，不是整套系统指标；`0.249 核` 是进程 CPU，不是整机或 VPU 利用率。

## 对文档口径的约束

- 可以说：“PL 1080p 原始画面已验证可直送 VPU 编码（H.264 900 帧 / 29.9 s）；与 NPU 人脸/PAD 共存时出现编码停帧，未部署，正式系统保持 960×540。”
- 不可以说：“已实现零拷贝”“1080p 30 fps 预览已上线”“芯片不支持 VPU/NPU 并发”“已定位唯一根因”。
- 共存失败的机理尚未定位；跨进程复现指向 MVX 驱动/固件与 NPU 的资源或复位契约，但这是方向，不是结论。

## 为什么在这里收口

- 跨进程、固定内存输入仍复现，说明仅拆进程不足以解决；但这些测试不能证明应用层一定无法修复。SDK/驱动初始化顺序、缓冲配置及采集与模型命令的排他边界仍需核对。
- 零拷贝收益有限：1080p 整帧 memcpy 约 2.43 ms/帧（约 7% 核），且厂商 API 没有 DMABUF 路径；优先级低于共存。
- 距 11-4 只剩数天，1080p 直送不应作为交付承诺；正式系统保持已验证的 540p。
