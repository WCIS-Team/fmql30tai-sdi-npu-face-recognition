# 普通SDI摄像头防照片实拍初测（2026-10-21）

在用户逐项确认摆放后，完成真人、手机静态人像、手机视频回放三组SDI实拍；真人6帧均被模型判为活体，手机静态人像5帧有效单脸均判非活体，手机视频6帧均判非活体。静态组另1帧检出两张脸，明确排除。用户没有打印照片，本轮未测打印攻击。

这是三个短片段的模型结果，不是防伪准确率、现场误放率或门锁安全验收。相邻帧高度相关，没有独立测试集，没有按这些分数选择新阈值。正式服务仍报告PAD `not_evaluated`，没有自动接入放行；模型分数不是安全放行概率。

## 采样与同帧绑定

新增板端有限采样入口`npu_photo/capture_pad_samples.py`，复用[已验证的原生识别输入路径](pl-encoder-native-input-20261021.md)。只在收到明确的人工就位回复后，以`--label`、`--operator-confirmed`和带时区的客户端确认时间启动；同意协助采样不自动当作当前场景标签。

采样前检查正式应用逐文件哈希、当前启动证明、原生程序及固定PAD包；正常停止正式所有者，确认相机末次DMA排空及SDK关闭，再启动唯一采样所有者。每组6帧，保留独立采集组ID，不能把6帧当成6次独立攻击尝试。

每帧运行现役YuNet检测及同帧PL源区全量一致校验，保存：

- 原始`source.rgb565`、逐位扩展到BGR后的无损`source.png`及两者SHA256。
- 相机启动ID、会话、帧号、采集请求和观察完成时间。
- 同一原始帧的浮点xyxy检测框、显式floor/ceil并裁边后的整数xywh框。
- 人工标签、检测数量、是否具备单脸PAD输入条件；无脸或多脸不指定猜测框。
- 双模型原始logits、各自softmax后融合分数、推理日志、模型提交及输入SHA。

相机当前正式路径为960×540 RGB565；保存PNG采用R5/G6/B5高位复制扩展，不能恢复已经丢失的原始8位颜色。此次输入属于实际RGB565摄像头域，并不是[原型文档](face-pad-minifas-20261018.md)的完整8位参考输入等价证明。PAD裁图仍用PS/OpenCV参考实现，`wcis_pad_preprocess.v`未接入或部署。

## 尚不能得出的结论

本轮只说明这些摆放下的手机照片/视频没有被模型判为活体。未控制或记录屏幕型号、亮度、环境照明、照片质量及人脸身份一致性；背景、屏幕边缘、距离和反光也可能帮助模型区分，而不是单凭面部生理信息。不能从这几个片段推断换手机、强弱光、远近、边缘被遮挡、打印照片或其他攻击下的效果。

后续安全验收应另采独立场次/人员、不同屏幕亮度与距离、打印及弯折照片，分开统计有效人脸条件下的攻击接受与真人拒绝，同时记录检测失败和多脸情况。校准与最终测试需要分离；本轮保持`security_calibrated=false`，不作“百分之百防照片”承诺。
