# 多人逐脸防伪接入（2026-10-27）

## 结果与范围

正式 8091 已切换至 `/root/wcis-face/apps/camera-pad-multi-20261027`。此前身份识别最多处理四张脸，防伪却在检测到多人时直接返回 `not_applicable/multiple_faces`；现在对同一组身份已处理的人脸逐一执行 PS/OpenCV 两尺度裁图和 NPU 双模型，并将结果按 `face_index` 对应到原检测列表。身份未知的人脸也执行防伪。

本次聚焦已有视觉功能，不新增门禁规则或 LLM 调用层。模型、原生执行文件、位流、人员库与录像模式均未改变。模型仍未校准；逐脸模型输出不能视为已完成防伪准确率验收。

## 实现过程

- `npu_photo/owner_pad.py`：解除多人整帧跳过，验证身份选择的数量、索引唯一性及人脸绑定。保留最多四张脸的工作上限；超过上限的人脸逐项返回 `not_evaluated/face_limit`。沿用身份识别选择的检测索引与处理顺序，不把排序后的第几项误当作检测索引。
- 同一份 RGB565 原帧只读取、核验、展开一次，随后逐脸生成两个 `80×80` 输入。所有推理复用现有硬件所有者和同一原帧租约；每张脸的耗时文件使用独立名称，避免覆盖。
- `presentation_attack_detection.faces` 是逐人结果列表，保留 `face_index`、裁图框、身份状态、两个模型的原始输出、融合结果与耗时。单脸保留旧顶层字段；多人顶层只报告 `evaluated`、`partial` 或 `stale`，不把不同人脸合并成一个真人/攻击判断。
- 保留从采集时刻起的三秒结果有效期。推理中或最终原帧核验时过期，已完成和未完成的人脸均明确失效；不会取消正在运行的 DMA，也不会复用旧结果补成功。硬件异常、错误回执或原帧变化仍使请求失败。
- `npu_photo/camera_requests.py`：共享响应的交付延迟同时更新整帧及每张脸的结果时效；过期时清零有效评估数量，不修改原共享结果对象。
- `npu_photo/serve_photos.py`：健康接口增加 `pad_face_limit=4` 和 `pad_result_scope=per_face`。
- `npu_photo/camera_panel.js`、`camera_panel.html`：检测框显示人脸编号，多人防伪按同一编号列出各自结果；缺失、重复或越界索引不能显示为有效逐人结果。保留占用退避、同帧核对及结果过期提示。页面说明改为最多四脸及未校准边界。
- 增加原图读取/颜色展开、裁图缩放、模型调用、原帧核验和总耗时记录，供后续按证据优化。

### 真实 NPU 回放

使用 2026-10-23 保存的 18 张 RGB565 原帧，仍明确标记为旧帧回放。其中 15 张为单脸，三张检测到两张脸：

- 15 张单脸的新输出与旧模型记录完全一致。
- 三张双脸均完成逐脸双模型推理，不再整帧跳过；各自结果为 `[model_non_live, model_live]`。每张脸与原单脸参考实现另行执行的原始 logits 最大差为 0，融合结果也一致。
- 三张双脸完整身份加防伪处理约 950.99、864.89、916.68 ms；其中防伪约 393.97、374.09、382.35 ms，裁图缩放合计约 3.70、4.11、4.00 ms。这是三个有限回放样本，不是多人实时吞吐或长稳结论；也不能把旧帧的整张标签当作每张脸的独立人工真值。
- 额外在测试适配器中将旧帧的两个检测 ROI 重复为四个，完成四 ROI / 八次真实 NPU 推理，输出与逐脸参考一致，PAD 约 766.38 ms。该用例只验证四 ROI 的顺序调用与结果隔离，**不是四个真实人的现场检测/身份/防伪验收**。其约 1292.74 ms 总处理时间包含两脸身份处理及四 ROI 防伪，不能标作四人完整链路速度。
- 每张回放帧的主流程仍使用正式三秒时效；额外参考调用仅在测试脚本中使用三十秒比较预算，未改正式时效。
- 候选另做四次及一次无人工标签的真实相机冒烟检查，原帧核验通过。两轮候选均正常退出、恢复原正式服务，人员库散列保持一致。
