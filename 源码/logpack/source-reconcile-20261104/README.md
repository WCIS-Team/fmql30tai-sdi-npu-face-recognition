2026-11-04：直接读取随包原上板 DCP，重新生成位流并打包 BOOT 完成。**重新生成的 BOOT.bin 与原上板版逐字节相同。**

## 验证结果

- DCP：`refclk-final.dcp`，SHA-256 `8e54e4cb42be0164d7925e9d2ef877745d663f79a87f4d8272414543441be2e8`。
- Vivado 2018.3 直接打开已布线 DCP，执行 write_bitstream，不重新综合、布局或布线；在独立目录测试随包恢复脚本通过。
- 原始 `.bit` 的 FPGA 配置数据为 5,979,916 字节，与原上板版逐字节相同。整个 `.bit` 的哈希可能因头部日期、路径等信息不同而变化，不能据此判定配置变化。详见 `direct-dcp/payload-proof.json`。
- Procise 按原配置执行 disable_icap 并打包。三个外部启动组件的哈希与原上板版一致，详见 `boot-component-hashes.json`。
- 最终 BOOT.bin 为 7,023,552 字节，SHA-256 `f6da96abbc0144ce5a48f4fa85aed6dab65067211b8932e8f4e4db87d5110297`，与原上板版完全一致。详见 `direct-dcp/boot-proof.json`。
- Procise 会将位流文件名写入镜像元数据。测试时使用 `_disable_icap.bit` 文件名，曾产生一个元数据字节差异；恢复原打包文件名 `ai7030_edif_top.bit` 后 BOOT 全文件一致。随包 BIF 和脚本已使用这个名字，文件内容仍经过 disable_icap 处理。
- Procise 的嵌套 source 未可靠更新 info script。恢复脚本会自动生成 `procise-command.txt`，显式传入当前目录，用户复制执行即可，无需修改源码路径。

原实现建立/保持裕量分别约 +0.005 ns、+0.004 ns；保留厂商 NPU 脉宽 -0.409 ns 违例记录，不能称为全部时序检查通过。本次没有改写板子或重新进行板端功能测试；已证明恢复出的启动镜像与原上板文件一致。只读检查时板端已有相机 DMA 保护标记，这属于当前运行状态，不能由镜像字节一致推断其已恢复正常。

## 源码修正

追溯 2026-10-16 JPEG/eMMC 工程、2026-10-18 双行缓存源码、2026-10-20 保留 DDR 实现的缓存修复和 SDI 引脚修复。已核对 101 份历史 RTL/约束哈希，设计导入清单修正为 113 项，约束为 4 项。

1. 顶层恢复 FAC1 + JPEG 包装层，补入三个 JPEG 业务模块、十二个编码器模块及第三方许可。
2. 恢复经过验收的双行缓存，不混入后续公平仲裁实验。
3. 恢复 eMMC 端口、PS 包装层和 BD，补入 eMMC 时序约束。
4. 恢复 FACE/JPEG 六组邮箱约束，保留 8 ns 请求、20 ns 响应的数据路径约束。
5. 保留完整版 SDI 的 U6/U5 引脚和上板 DCP 的 USERID 设置。

从原 DCP 读出确认：FAC1/JPEG 实例、512 位第二行缓存、eMMC 端口和 IBUFDS_GTE2_X0Y1 参考时钟缓冲均存在。详见 `release-structure.txt`、`source-reconciliation.json`。

## 源码重新构建的验证边界

修正后的 24 项 IP 综合、顶层综合、五个人脸预处理仿真及两种 JPEG 格式仿真通过。测试驱动最初漏列包装层依赖和向量路径，补齐后通过，没有为通过测试修改 RTL。

RTL、XCI、PRJ 和 XDC 与提交输入字节一致；BD 重新生成只改变 4 个 XCI 自动命名及 2 个 ID_WIDTH 的 value_src 元数据，参数值和接口未变。详见 `consumed-inputs.json`、`bd-regeneration-diff.json`。

曾尝试以 DCP 作增量参考，初始单元匹配率 99.98%，布局复用率 99.96%，连线复用率 99.77%。在初始布线阶段根据新的复现方式主动停止，没有生成这条路线的新位流，也未完成其 DDR 复用和板测验收。这些百分比不是功能等价证明。

最终交付步骤采用直接恢复 DCP，属于“源码 + 保存的实现资源”复现，不是不依赖 DCP 的纯源码构建。历史完整重布线候选出现过 DDR 错误，不能删除 DCP 后宣称功能仍已验证。
