# 01 板端部署流程与命令（实测版，2026-11-04）

对应提交包 README 的 §一 + §三。所有命令在板端 root 下执行；本机为 Windows（Git Bash + OpenSSH）。

## 0. 连接板子

```sh
# 一次性：装公钥（首次连板，或 key 被拒时排查见 02 文档坑#3）
echo 'ssh-ed25519 AAAA… comment' >> /root/.ssh/authorized_keys   # 板端执行

# 之后本机全部走 key：
ssh -i ~/.ssh/id_ed25519 root@192.168.1.113
scp -i ~/.ssh/id_ed25519 <file> root@192.168.1.113:/root/
```

## 1. §一 换 BOOT

板上原状（出厂态）：FAT 启动分区 `mmcblk0p1` 挂载点自建 `/root/bits`，厂商 BOOT.bin SHA `c87b7959…`。

```sh
# 1) 备份厂商启动文件（只做文件级备份即可，整分区 dd 镜像没必要，见 02 坑#8）
mkdir -p /root/boot-backup-vendor-20261104
mount -t vfat -o ro /dev/mmcblk0p1 /root/bits
cp -a /root/bits/. /root/boot-backup-vendor-20261104/
umount /root/bits

# 2) 上传提交包 4 个启动文件到中转目录并校验
sha256sum BOOT.bin Image fmqlmp-verify.dtb uEnv.txt
# 期望：BOOT.bin=f6da96abbc0144ce…  Image=ee88eae627df17fd…  fmqlmp-verify.dtb=e7edf0bc5eb31485…  uEnv.txt=a13c985eb5031d75…

# 3) 写入 FAT 并校验
mount -o remount,rw /root/bits        # 若未挂载：mount -t vfat -o rw /dev/mmcblk0p1 /root/bits
cp -f BOOT.bin Image fmqlmp-verify.dtb uEnv.txt /root/bits/
sync
sha256sum /root/bits/BOOT.bin /root/bits/fmqlmp-verify.dtb   # 必须与期望一致
mount -o remount,ro /root/bits && umount /root/bits
sync
systemctl reboot
```

实测：出厂 Image/uEnv 与提交包逐字节相同（不用换），实际只换 BOOT.bin 和 fmqlmp-verify.dtb。
重启后验证：BOOT SHA 变为 `f6da96ab…`；`lsblk` 出现 `mmcblk1`（29.1G eMMC，p1=ext4 LABEL=WCIS_FACE）。

## 2. §三-1 上传运行文件 + 装依赖

```sh
# 本机：上传 64MB 包（实测 6 秒）
scp -i ~/.ssh/id_ed25519 board-run.tar.gz root@192.168.1.113:/root/

# 板端：
cd /root
sha256sum board-run.tar.gz          # 9c6669bdfcfe86fc…（11-04 拍板修订版；与本机比对）
tar -xzf board-run.tar.gz           # 解出 /root/submission/
cd ~/submission
apt-get update
DEBIAN_FRONTEND=noninteractive apt-get install -y \
  python3 python3-numpy python3-opencv ffmpeg curl util-linux e2fsprogs procps \
  ./board/sdk/*.deb
```

注意：板端 rootfs 是 Ubuntu 20.04 (focal)，apt 走中科大 ports 镜像 + armnn PPA，实测 ~4 分钟。
SDK deb 3 个：`Icraft_3.39.0_onchip` / `CustomOp_3.39.0_onchip` / `IcraftMdzThirdParty`。

建议顺手停掉自动升级（它占 46% CPU / 194MB 内存，还会抢 apt 锁）：
```sh
systemctl stop unattended-upgrades
```

## 3. §三-2 渲染安装树 + 安装 + 起 storage

board.json 填本板真实值：

```json
{
  "data_device": "/dev/mmcblk1p1",
  "data_mount": "/mnt/wcis-data",
  "data_uuid": "67104a06-74a6-4268-a124-269d1b232a28",
  "sd_device": "/dev/mmcblk0p1"
}
```

```sh
cd ~/submission
python3 board/render_install.py --config board.json --out install-tree
# ↑ 内部会按 filelist.json 逐文件校验 reference_release/ 和 board/ 的 SHA256，全对才产出

for unit in install-tree/rootfs/etc/systemd/system/*.service; do
  if systemctl cat "${unit##*/}" >/dev/null 2>&1; then
    echo "已有服务 ${unit##*/}，请走原工程的升级流程"; exit 1
  fi
done
cp -a install-tree/rootfs/root/wcis-face /root/
mkdir -p /root/wcis-camera-preview
touch /root/live.disabled
cp -a install-tree/rootfs/etc/systemd/system/*.service /etc/systemd/system/
systemctl daemon-reload
systemctl start wcis-face-storage.service
findmnt -rn -S /dev/mmcblk1p1      # 应显示挂载在 /mnt/wcis-data
```

## 4. §三-3 启动识别

```sh
# 确认厂商演示进程已退出（出厂态新 rootfs 天然没有）
pgrep -af 'login.py|ai7030|demo' || echo no-vendor-demo

# 若启动分区被挂了先卸载（识别服务启动时会自己只读挂它做校验）
umount /root/bits 2>/dev/null

systemctl start wcis-face-photo.service
sleep 20
systemctl --no-pager status wcis-face-photo.service | head   # active (running)
curl --fail http://127.0.0.1:8091/api/health        # "status":"ready"
curl --fail http://127.0.0.1:8091/api/camera/status # frame_id 持续增长
```

**有旧数据的板（本板）**：`/mnt/wcis-data/wcis-face/` 已存在（10 月的人员库），
README 里「cp 空库」那步必须跳过，直接启动服务即可，旧库自动被使用。

## 5. §三-4 预览与录像

```sh
systemctl start wcis-sdi-vpu-view.service wcis-face-recording.service
ss -tln | grep 809                  # 8091/8092/8093 全部 LISTEN
```

浏览器验收（人工）：8091 登记人脸→识别；8092 连续预览；8093 录像+回放。
