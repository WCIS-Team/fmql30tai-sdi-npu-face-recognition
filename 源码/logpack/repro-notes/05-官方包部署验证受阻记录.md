**验证命题**：官方包 `wcis-official.tar.gz`（85.3 MiB，源码+refclk-final.dcp+模型）+ 最少外部补件 → 板端能否完整跑通。
**结论：通过**。自产 BOOT 与提交版逐字节一致（`f6da96ab…`），四服务全绿，相机精确 30fps，eMMC 人员库沿用。外部补件共 14 件（见末尾）。本文只记受阻点。

## 受阻清单（按撞上顺序）

1. **render_install 包校验拒绝自编 ELF（提交包设计缺口，已修复）**
   `Package asset checksum mismatch: reference_release/app/wcis_camera_owner`——filelist.json 记录提交版二进制哈希，评委按 §二 自编必然撞同款。**最终修法（语义修正）**：五个 ELF 是可再生资产（§二 本就允许重编），`render_install.py` 改为对它们只做「存在且为 aarch64 ELF」完整性检查（ELF 头 magic+class+type+machine 比对，OSABI 不锁），模型/boot/deb 仍按清单哈希逐字节校验；filelist.json 里 5 条 ELF 条目**还原为提交版原哈希**（评委仍可据此对照全量包验证提交版）。板端与本地均已验证「还原清单+自编 ELF」通过。连带坑：render_install.py 自身也在清单里，改它之后清单的 board/render_install.py 条目要同步新哈希（正当内容变更）。
2. **容器 x86_64 静默编出 x64 ELF**
   `fpai-ub2004` 容器是 x86_64（tag 里的 arm64 指 kit 目标不是主机架构）。npu_photo 的 CMakeLists **没有** ps_app 那条 `CMAKE_SYSTEM_PROCESSOR` 断言，不传工具链时静默用主机 g++ 编出 x64 ELF。修法：注入 aarch64 工具链文件（容器自带 `/usr/bin/aarch64-linux-gnu-g++` 9.4）。
3. **工具链 FIND_ROOT_PATH 漏 /usr**
   cross 模式下 `find_package(icraft-zg330backend)` 找不到 kit config（config 在 /usr/cmake/）。`CMAKE_FIND_ROOT_PATH` 必须含 `/usr`。
4. **podman Windows 挂载路径被 Git Bash 转换**
   `-v "...:/src"` 的容器路径 `/src` 被 MSYS 转成宿主 Git 安装路径，podman **静默挂载空目录**。必须 `MSYS_NO_PATHCONV=1`。
5. **部署脚本漏装 SDK deb（流程疏漏）**
   `apt-get install ./board/sdk/*.deb` 这步没进 step2 脚本 → `libicraft_zg330backend.so` 缺失 → owner 启动即退（`Owner exited without an active request completion`）→ photo failed。补装后恢复。
6. **photo 单元失败后残留 ffmpeg 占 cgroup**
   单元 `SendSIGKILL=no`+`KillMode=mixed`：失败残留的 ffmpeg 使 systemd 拒绝再次启动（"Will not start SendSIGKILL=no service while processes exist"）。修法：手动 kill 残留 PID + `systemctl reset-failed`。**评委自编替换 owner 调试时会踩同款**，值得在 README 提一句。
6b. **hardware-review-required.json 本 boot 隔离标记**
photo 服务一次失败后 `camera_interlock.py` 在 `wcis-face/` 写入隔离标记，同 boot 内再次启动一律拒绝（"no automatic SDK reuse"，设计=要求人工复核硬件）。人工确认后 `rm /root/wcis-face/hardware-review-required.json` 即可重启。评委调试自编 owner 时必踩，已写进两份 README §二第 3 条。
7. **换 BOOT 重启后网络 18 分钟不可达（坑#5 重演加长版）**
   板端 journal 显示 00:39:01 一次干净的 DISCOVER→OFFER→ACK（无 INIT-REBOOT、无双客户端 RELEASE），uptime-s=00:20:53——**开机后 18 分钟才完成 DHCP**。更指向 DHCP 服务器/网络侧迟到。同日早间厂商 BOOT 下是 12 分钟。未定位，两端日志拼不出 L2 发生了什么。
8. **/root 属主再次变 Windows uid（197610:197121）**
   卡被 Windows ext4 工具碰过后属主污染，sshd StrictModes 拒公钥。`chown root:root /root` 修复。
9. 小疏漏三则：board.json UUID 占位符未替换、tar 在 submission 内部打导致解包少一层前缀、Vivado 把 bitgen.log/jou/webtalk 写在 cwd（staging 根污染，上传前清理）。
10. ~~Procise ps1 报 "BOOT partition comparison failed"~~——内部比对步骤误报，顶层 SHA 逐字节一致（`f6da96ab`），非阻塞。
