# FMQL30TAI 一键编译安装（Shell / Python 3.8）

> **公开仓库与完整安装包不同。** GitHub 版排除了 `payload/runtime/reference_release/` 和 SDK deb，并非下文所说的完整压缩包。下列安装步骤须在取得合法且匹配的完整资源后执行；`MANIFEST.json` 保留完整包的历史清单，不表示公开版具备全部文件。模型来源、缺失资源及许可见 [模型说明](../docs/MODELS.md) 和 [第三方声明](../THIRD_PARTY_NOTICES.md)。

将压缩包完整解压为一个文件夹。在**编译电脑**上任选一个入口，不要两个同时运行：

```sh
# Shell 入口
sh install.sh

# Python 3.8 入口
python3.8 install_py38.py
```

两份入口共享 installer/ 内的安装逻辑，Shell 入口也需要 Python 3.8；不是两套独立维护的安装实现。Linux 文件管理器支持“在终端运行”时也可以这样打开 install.sh；不要依赖系统对脚本的默认双击动作。Windows 可直接用已安装的 64 位 Python 3.8 运行 install_py38.py，不使用 CMD 批处理入口。

提示后输入板卡 IP，再隐藏输入板卡 root 密码。用户名固定为 root；密码只在本次运行的内存中使用，不保存在包、日志或命令行参数里。

脚本使用随包 BOOT，只重新编译五个 PS 程序。不需要运行 Vivado 或 Procise；本包不包含 FPGA 源码、DCP 或 FPGA 构建脚本。

## 开始前

- 电脑：Linux x86_64（glibc 2.17 及以上）或 Windows AMD64，已安装 **CPython 3.8.x 64 位**。本包依赖按 3.8 配套，不使用旧版便携 Python 3.12。已启动可用的 Podman 或 Docker，并已导入复现记录使用的 iCraft Linux 编译容器（例如 fpai-ub2004）。容器须带 AArch64 GCC、CMake、iCraft 3.39.0 开发库、`/ModelzooDeps/aarch64/Static` 和 ARM64 zlib 开发库（`/usr/lib/aarch64-linux-gnu/libz.so`）。仅安装 Windows iCraft 图形程序不足以编译本项目的 PS C++ 程序。
- 脚本自动查找名字包含 icraft/fpai 的本地容器镜像，并实际检查编译器及 SDK；多个可用镜像时提示选择。自定义镜像名可填入 `settings.json` 的 `container_image`，例如 `my-sdk:3.39`；不要在此文件填写密码。未找到环境时会在改板前停止。
- 板卡：FMQL30TAI 完整版，已有厂商 AArch64 Ubuntu Linux，root 可通过 SSH 密码登录。电脑和板卡网络互通；板卡能访问它现有的 Ubuntu 软件源，以安装 Python/Numpy/OpenCV/FFmpeg 等系统依赖。
- SD 系统已经能启动；eMMC 有一个可用的 ext4 数据分区。脚本不会给空盘分区或格式化。若出厂 DTB 暂未启用 eMMC，先自动更新本包启动文件并重启，再重新检测。
- SDI 摄像头：魔客仕（MOKOSE）**SHD30**，2.8–12 mm 变焦镜头，独立 DC 12 V / 1 A 供电。断电时用 75 Ω BNC 同轴线将摄像头 `SDI OUT` 接至 FMQL30TAI 完整版的 `XS1 / SDI0` 输入，上电后使用 HD-SDI（SMPTE 292M）1080p30（1920×1080 逐行、30 帧/秒）。[SHD30 厂家资料](https://www.mokose.cn/productinfo/117098.html?templateId=1133605)
- 保持板卡电源和网线稳定。每次在电脑预留约 1 GB、板端根分区至少 800 MiB 可用空间用于暂存和备份。

两种宿主平台的 Python 3.8 SSH 依赖已放在 vendor/，启动时自动选择，无需联网 pip 安装，也不需要 PuTTY 或 SSH 公钥。依赖固定版本见 requirements-py38.txt，原许可证随库保留。

Shell 默认先找 python3.8，再检查 python3 是否为 3.8。如果解释器不在 PATH，可指定：

```sh
PYTHON38=/完整路径/python3.8 sh install.sh
```

Windows 的 Git Bash/MSYS2 也可以使用 Shell 入口，但应指定 Windows Python 3.8 的可执行文件。Linux 的运行记录放在 XDG_STATE_HOME（默认 ~/.local/state）下，不会写入安装包目录。

## 自动执行的操作

1. 检查安装包的逐文件 SHA-256，检查已有编译容器。
2. SSH 登录板卡，只读确认系统、SD/eMMC 分区、真实 UUID 和已有服务。首次连接记录该 IP 的主机指纹；以后指纹变化时停止。
3. 在新的容器运行目录编译 `wcis_camera_owner`、`wcis_face_cached`、`wcis_face_pl_retained`、`wcis_face_pad`、`wcis_face_npu`，检查输出确实为 AArch64 ELF。容器内不访问网络，复用已有镜像，不修改原 SDK 镜像。
4. 上传并核对安装文件。自动识别 SD 启动分区；BOOT、Image、DTB、uEnv 与包内相同则跳过写入。需要更新时先备份、写入校验，然后正常重启并等待恢复网络。
5. 安装三个随包 SDK deb 及系统依赖，检查动态库；按本板 UUID 生成服务配置和新程序哈希，安装四项服务。
6. 保留已有人员库和录像，只初始化缺少的目录和空库。检查主站健康、模型就绪、相机同一会话的帧号持续增加以及三个网页，成功后设置开机启动并打开主站。

板上已有视觉安装时，脚本会说明更新内容并要求输入一次 `UPDATE`。正常的新板流程不要求手写命令。失败时终端返回非零退出码并显示错误信息，不会把失败显示为成功，也不会自动切换成未经说明的预编译部署。

## 打开网站

- `http://板卡IP:8091/`：主站、人脸登记与识别。
- `http://板卡IP:8092/`：实时预览。
- `http://板卡IP:8093/`：录像和回放。

自动检查通过后，还需现场登记/识别测试人脸、看预览、录一段并回放；脚本不会代替这些人工验收，也不承诺 PAD 安全标定和长期稳定性。

## 失败与日志

- 本机日志与工作目录：Linux 为 `${XDG_STATE_HOME:-$HOME/.local/state}/fmql30tai-installer/runs/日期时间-编号/`；Windows 为 `%LOCALAPPDATA%\FMQL30TAI-Installer\runs\日期时间-编号\`。其中 `compile.log`、`board-install.log` 和 `acceptance.json` 分别记录编译、板端执行与成功验收。失败时不生成成功验收记录。
- 板端文件：`/root/wcis-install-runs/日期时间-编号/`；`backup/` 保存被替换的启动文件、已有服务和应用树。人员库及录像仍在 eMMC，不移入应用备份。
- 当前启动存在 `hardware-review-required.json` 保护标记时，脚本停止，不删标记、不强行重试 SDK。先保留日志检查故障，再按项目维护说明正常重启；重启不等于根因已消除。
- 残留相机/推理/编码进程、启动分区已被其他程序挂载、多块候选数据盘、UUID 异常等情况均停止并说明。不会批量杀进程、清空数据盘或改全局 DHCP 配置。
- 更新启动文件后最多等网络恢复 20 分钟。若 IP 改变或超时，先确认实际 IP 和串口状态；不要反复断电。重新运行会再次校验文件，已有相同 BOOT 不会重复写入。
- 编译容器不可用时，先启动并配置老师现有环境再重试。本脚本不会自动下载安装大型厂商工具或绕过工具许可。

可选诊断：`sh install.sh --check` 或 `python3.8 install_py38.py --check` 校验本机包并加载离线 SSH 组件；将 `--check` 换为 `--preflight` 则检查编译环境并只读查询板卡，不上传、安装或重启。

## 包内文件

| 文件/目录 | 用途 |
|---|---|
| install.sh | Shell 启动入口，转入共享的 Python 3.8 安装逻辑 |
| install_py38.py | Python 3.8 启动入口 |
| installer/ | 安装逻辑、PS 构建脚本与工具链配置 |
| vendor/ | Linux x86_64 / Windows AMD64 的 Python 3.8 离线 SSH 依赖及原许可证 |
| requirements-py38.txt | 固定依赖版本清单 |
| source/ | PS C++ 构建输入；没有 FPGA 源码 |
| payload/runtime/ | BOOT/Image/DTB/uEnv、模型、网页、Python 服务、SDK deb 及安装渲染工具 |
| MANIFEST.json | 本包固定文件清单和 SHA-256；可编辑的 settings.json 单独列出 |
| settings.json | 可选指定已有容器引擎/镜像，默认自动检测 |

随包五个预编译 ELF 保留为原交付资源；正常安装时会用本次成功编译的输出替换暂存副本，再自动渲染对应服务校验值。原始包不被编译产物覆盖。

## 本轮验证范围（2026-11-04）

- 在实际 Ubuntu 20.04.5 容器中，使用 GCC 9.4.0、CMake 3.16.3、iCraft 3.39.0、ModelzooDeps 和 ARM64 zlib 开发库，由交付包的 `find_compiler` / `compile_ps` 自动检测环境并运行 `build_ps.sh`，五个 PS 目标全部构建成功。构建容器禁用网络，源码只读挂载，输出通过 AArch64 ELF 检查。驱动使用 Windows CPython 3.8.10。
- Linux 容器内 CPython 3.8.10 的 Shell 入口和 Python 入口离线检查通过，随包 Linux SSH 依赖可加载；十项边界/故障注入测试通过。此前 Windows CPython 3.8.10 的两个入口检查也已通过。
- 新编译程序经实际 `make_payload` 打包、解包和完整性校验，再离线生成四项服务配置，通过；相机主程序哈希与服务配置一致。这里只生成临时安装树，没有向实际系统安装服务。
- 首次容器试验发现缺 ARM64 zlib 开发库导致链接失败；补齐后全部通过，安装器也已增加对此依赖的提前检查。实际缺库镜像会被拒绝。详见 `容器实测记录.md` 和 `validation/`。
- 仍未证明“同一 ZIP 在空白老师环境中从头到尾安装成功”：本轮没有执行板端 boot/install 阶段，没有上传新程序到板卡、重启或进行人脸/录像硬件验收。容器编译成功不能代替这些板端步骤。先前的板端只读预检记录仍仅证明预检结果。

原始复现记录中的凭证和旧源码 FPGA 构建步骤不随包发布。
